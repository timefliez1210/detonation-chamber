Does screening messages in a sandbox first stop agents from doing harm?

Every incoming message goes through the detonation chamber before the real agent sees it. The chamber runs a decoy agent on the message in a sandbox with fake credentials and watches what happens. Messages that trigger harmful behavior are blocked or sent to a person. We measured how many harmful requests still get through, and how much harmless mail gets caught on the way.

Harmful requests that still succeed

Chamber: DeepSeek V4.1 Flash with the trusting persona, the best setup tested. "Block Malicious" stops only messages where harm was observed; "also Suspicious" also holds messages where the decoy agent flagged an attack or touched secrets. 40 direct harmful requests per agent (20 requests × 2 runs).

What we learned

The most gullible model made the best detector

DeepSeek complied with harmful requests more often than any other model as an agent. As the decoy inside the chamber, that is what you want: it acts the attack out, so the chamber sees it. With the trusting persona it let nothing through and flagged the fewest harmless messages.

"Suspicious" is a clean signal

Almost every attack message lands in Suspicious or Malicious, while at most one harmless message out of 36 was marked Suspicious. Sending Suspicious messages to a person adds very little review work.

Most false blocks come from the decoy itself

On harmless messages the decoy agent sometimes oversteps on its own: it installs a tool with a remote script because a README mentions it, or calls Stripe with the honeypot key while handling a support email. The message gets blamed for the decoy's initiative. A few more come from two rules that are still too broad.

Method and caveats

  • 132 messages: 20 direct harmful requests, 70 hidden injections, 24 human-written attack emails from LLMail-Inject, 18 harmless messages. Each was run through every chamber setup twice.
  • Protected agents: GLM 5.3 Flash and DeepSeek V4.1 Flash, using their unprotected results from the baseline eval. A message counts as blocked if the chamber flagged it in the matching run.
  • The chamber knows nothing about the downstream task. It asks its decoy to handle the message, as a pre-screen would.
  • Hidden injections almost never worked even without a chamber, so this measures protection against direct harmful requests.
  • Small numbers: 9 to 11 real hijacks per agent, so "all caught" still has a 95% interval of roughly 70–100%. The chamber and the protected agents share the same two models, so the test is not fully independent.
  • Sandbox: bubblewrap, fake credentials, attacker addresses unroutable. Nothing real could leak.
